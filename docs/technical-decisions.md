# 当前依赖与统一动效决策

日期：2026-10-09。状态：已采用并实现。本文记录当前代码的选择；早期设计研究继续作为历史背景。

工具链：`go.mod` 指定 Go 1.27.1；Docker 构建固定 Go 1.27.1 和 Node 22.23.1 基础镜像。最终服务端基于 scratch，只有静态 Go 程序、CA 和数据/临时目录；服务器构建不依赖浏览器安装阶段。可选的 `mcp` 构建目标安装 Chromium Headless Shell、fontconfig、Noto Sans CJK 常规/粗体、CA 和 dumb-init。Chromium 的系统包来自镜像构建时的 apt 源，目前没有另行固定其补丁版本。容器设置 `JIANXI_CHROMIUM_HEADLESS_SHELL=1`，通过 Puppeteer 的 `headless: 'shell'` 模式编译静态 SVG；[官方说明](https://pptr.dev/guides/headless-modes) 将此模式用于无需完整浏览器功能的自动化任务。

Playwright CLI 是开发时调用的浏览器验证工具，目前不在项目的 npm 直接依赖清单中，不是服务器或读者运行页面所需的库。本地 `node_modules` 另有两个未声明的 Sharp/WASM 相关安装项；`npm ci` 的正式安装范围仍由锁文件决定。

浏览器没有 React、Vue、UI 组件库或客户端 Markdown/图表渲染器。GSAP、霞鹜文楷、KaTeX CSS/字体从本站提供，没有必需的 CDN。可选的外部网络服务包括百度推送/访问统计、哔哩哔哩播放器和文章外链媒体，按实际配置或内容启用。

代码围栏在 Goldmark AST 中收集，同一篇文章的代码块一次交给固定 Node 编译器，复用一个 Shiki highlighter，只加载实际用到的语言。语言别名使用 Shiki 内置映射，缺省或未知语言回退为 `text`；正文里的 `math` 和 `mermaid` 围栏仍走各自的编译分支。高亮失败会阻止编译，不静默丢失高亮。输出仅含 `pre/code/span` 片段及局部行内颜色，保留代码文本、复制按钮和横向滚动，不生成全局 CSS。禁用 JavaScript 时仍可阅读高亮代码。库和语法资源来自本地 npm 安装，不通过运行时 CDN 加载。[Shiki 官方用法](https://shiki.style/guide/install)。

## 霞鹜文楷加载策略

`npm run assets` 保留上游按使用频率分组的 `unicode-range`，仅复制常规 400 与粗体 700 两个字重，共 194 个 WOFF2 分片、约 8.82 MiB 完整字库。磁盘总量不等于单页下载量；浏览器只请求实际文本及字重所需的分片，并自行并行调度。正文、菜单、输入控件均使用文楷；代码保留等宽字体，数学公式继续使用 KaTeX 字体。

构建生成共享的 `web/font-head.html`，前台、404、预览及后台直接通过 `<link>` 发现同一份字体 CSS，不通过 `@import` 或 JS 串行加载。仅预加载约 34 KiB 的常规 Latin / 标点 / 高频字符分片，不预加载整个字库。`font-display: swap` 使下载期间文字仍可读，失败时回退系统楷体 / 中文字体；页面导航或输入新字符时由浏览器继续按需请求。生产 HTTPS 建议由反向代理提供 HTTP/2 或 HTTP/3，使同源分片可以复用连接并行传输；本地 HTTP/1.1 则服从浏览器连接数限制。

字体 CSS 与 WOFF2 均以内容 SHA-256 的前 16 位命名，服务端对存在的这些资产返回 `Cache-Control: public, max-age=31536000, immutable`，跨页面复用并长期缓存；更新字库或规则后 URL 自动变化。其他可变静态文件与不存在的字体返回 `no-cache`，避免部署后继续使用旧样式或缓存 404。SIL OFL 与分包工具许可证随资产保留。字体来源：[霞鹜文楷](https://github.com/lxgw/LxgwWenKai)、[Webfont 分包项目](https://github.com/chawyehsu/lxgw-wenkai-webfont)。

2026-10-08 本地 Chromium 演示首页实测：首次请求 18 个分片、字体正文 866,348 字节（约 846 KiB），存在重叠请求；第二次访问字体网络传输 0 字节。CDP 确认标题实际使用 `LXGWWenKai-Bold`。此下载量随正文字符与字重变化，不是所有页面的固定预算。`output/playwright/jianxi-wenkai-review.cjs` 同时验证 1440 / 768 / 390 / 320 像素布局、代码等宽字形及禁用 JS 且阻断字体下载时的阅读回退；`go test ./...` 检查前台 / 后台字体入口、全部分片有效性、GET / HEAD 类型和缓存响应。

文楷字号整体增加 2px：文章正文桌面 17px、手机 16px，关于页介绍桌面 16px、手机 15px。导航、摘要、标签与后台文字同步增加；导航行高、按钮、图标与头像略微放大，正文行距保持约 2 倍。手机目录按新的 46px 行高计算面板尺寸。`output/playwright/jianxi-type-size-review.cjs` 验证 1440 / 1024 / 768 / 390 / 320 像素下公开页面、搜索与手机目录；后台首页、内容、设置与备份页也通过桌面与小屏溢出检查。

## 动画采用 GSAP 一个引擎

所有带时长的界面动画统一交给 GSAP：导航高亮、侧栏、搜索、手机目录、后台确认框、页面转场、按压反馈及时间线条目悬停。CSS 负责布局、静态外观和即时状态反馈，项目自己的组件不再使用 CSS transition、CSS keyframes、Web Animations API 或手写逐帧动画循环。

统一参数入口是 `internal/blog/web/static/motion.js`。它暴露已加载的 GSAP 实例、一份减少动效设置、命名缓动和时长表。公开页及后台都在 GSAP 之后加载此模块，各业务控制器引用这份配置；不再各自复制弹簧公式和时长常量。

弹簧采用 `jianxi.spring`：480ms 的固定阻尼响应，带轻微越过终点后的回弹。曲线经 GSAP 官方的 [`registerEase`](https://gsap.com/docs/v3/GSAP/gsap.registerEase%28%29/) 注册，只决定进度到位移的映射；帧调度、插值、时间线、覆盖和中断仍由 GSAP 完成。当前是固定曲线的弹簧效果，不是持续积分的物理模拟；重新选中目标保留当前渲染位置，但不承诺跨目标保持物理速度。

| 动效角色 | 统一时长 | 缓动与边界 |
| --- | --- | --- |
| 面板、高亮、回到原位 | 480ms | `jianxi.spring`，轻微回弹 |
| 后台确认框收回 | 420ms | 同一弹簧曲线 |
| 页面标题 / 正文入场 | 280ms / 340ms | `power3.out`，标题先行，正文落后 45ms；最多六个可见区块，总错峰不超过 105ms |
| 等待 / 页面退场 | 150ms / 160ms | 等待时旧内容保持 72% 不透明、上移 4px；内容就绪后淡出并上移至 8px |
| 淡入/淡出 | 200ms | GSAP 默认平滑减速 |
| 悬停背景/边框 | 150ms | `power1.out`；CSS 无计时过渡 |
| 微反馈 | 100–160ms | 使用公共时长表中的对应角色 |

界面状态、焦点和网络请求立即处理。多步动画用 GSAP timeline 的位置参数编排，不以 timeout 延迟导航或业务提交。相同目标的高亮动画不因页面数据到达而重启；新目标从当前渲染位置接续。布局变化或减少动效设置切换时，各控制器负责到达正确终态及清理旧节点。

### 页面加载和点击转场顺序

首次加载保留服务端 HTML，侧栏与顶栏直接可用。标题和首屏内容按顺序从 8px 位移回到原位；如果脚本较慢、正文已经完成首次绘制，保持其不透明，避免先出现再隐藏。

点击时立即移动导航高亮并启动请求，旧内容轻微退后且仍可点击。请求与所需样式均就绪后，旧内容执行 160ms 退场，提交新地址、内容和面包屑，挂载页面交互，再让标题和正文从 12px 位移淡入。只对可见内容区块施加动效，不同时动画父子节点；侧栏、顶栏和内容根节点始终保持不透明。

超过 180ms 的请求在顶栏下方显示细线，GSAP 驱动循环表示等待，没有虚假的百分比进度。新内容入场时移除加载线。连续点击从当前显示值接续，取消旧请求与动画，只有最后一次请求可以提交；点击正在显示的页面可以取消等待并恢复旧内容。

历史恢复和跨页锚点采用 200ms 淡入、零位移，避免影响恢复位置。同页锚点先清理转场再由浏览器滚动。系统切换到减少动效时释放等待中的动画、恢复可操作状态并直接到达当前业务终态；网络异常仍回退到原生导航。

上述序列在 `motion.js` 的 `createPageSequence` 中使用 [GSAP timeline 的标签和位置参数](https://gsap.com/docs/v3/GSAP/gsap.timeline%28%29/) 编排，导航模块管理请求、提交和取消，`site.js` 只挂载内容交互，避免重复控制同一个页面的入场。

导航代码的 `requestAnimationFrame` 只用于合并历史滚动位置记录；编译子进程超时和验证工具等待只用于业务控制。这些不是另一套动画引擎。

系统选择减少动效时，公共模块返回零动画时长；侧栏、搜索、目录和后台控制器完成当前终态，保留原有业务状态。瞬时 `gsap.set`、拖动时直接设置宽度和无 JS 的静态交互继续可用。

### 搜索筛选和弹层操作

搜索页分类、标签由 `filters.js` 渐进增强为自定义菜单，保留隐藏的原生 select 参与 GET 表单；无 JS 时直接使用原生字段。组件使用 combobox、listbox、option 和 aria-activedescendant，键盘探索与实际提交分开，支持方向键、首尾、字符查找、Enter/Tab 提交和 Esc 取消，参考 [W3C 的 select-only combobox 交互说明](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)。菜单展开收起引用公共 GSAP 动效设置，减少动效时完成当前终态；页面卸载时释放监听器及动画。

搜索弹层空关键词不显示介绍文案；底部改为关闭和查看全部结果的图标按钮，通过 aria-label 和 title 保留操作名称，全部结果链接随当前关键词更新。没有新增 npm 包。浏览器回归位于 `output/playwright/jianxi-search-controls-review.cjs`，覆盖真实筛选搜索、键盘取消/提交、历史恢复、图标操作、窄屏与无 JS 回退；未做独立读屏软件验证。

## 保留现有内容渲染链路

Markdown、代码、公式和图表在发布前生成静态结果，保持无 JS 阅读和搜索引擎可见。KaTeX、Mermaid/Puppeteer 和 Sharp 的功能边界不同，动画统一不需要替换它们。

发文电脑的 MCP 编译镜像包含 Go MCP 进程、Node、Chromium Headless Shell 和渲染依赖；服务端镜像仅包含 Go 与静态资源。运行依赖独立为 `runtime-deps` 构建阶段：排除仅用于生成嵌入资源的 GSAP 与霞鹜文楷 npm 包，以及 JS source map 和 TypeScript 声明文件，保留运行 JS、动态模块、原生库及许可文件。前台字体、GSAP 和 KaTeX 静态资源继续嵌入 Go 程序。图表只使用 sans-serif，因此容器保留 Noto Sans CJK 两个字重，去掉 Noto Serif CJK；公式和图片库仅在对应任务中加载。

本地 MCP 的主要体积和维护成本来自图表浏览器及图片原生库。升级通过清单与锁文件进行，并执行对应的公式、全部受支持图表类型、图片或交互回归，不在服务器运行时安装 `latest`。

当前界面规模使用服务端模板、静态 HTML 和少量原生 JS 足够。此轮采用公共动画配置模块，避免再引入前端框架、第二套动画库或自研动画播放框架。新增外部依赖应给出它解决的具体功能，以及已有依赖不能承担该功能的证据。

## 落地与验证

已把三处弹簧定义合并到 `motion.js`，将时间线悬停从 CSS transition 迁移到 GSAP，并让公开页和后台引用相同配置。页面切换时释放旧悬停监听器和动画。

验证包括真实本地站点的连续导航、弹簧中间帧、悬停及减少动效切换、搜索、手机目录、历史位置和无 JS 阅读。后台确认动画通过一个使用真实后台脚本和样式、只执行取消操作的浏览器 fixture 验证；该 fixture 不代替后台发布或密钥操作的业务验收。

页面加载序列的独立浏览器回归位于 `output/playwright/jianxi-page-sequence-review.cjs`：采样真实页面退场和标题/正文入场中间帧，另外通过截留实际页面请求验证等待时可读、取消恢复、退场/入场被新点击打断、动效偏好变化和手机抽屉。它和现有导航回归一起运行；没有发布测试文章。

## 本地编译与服务端校验

MCP 工具只接受受限 Markdown、结构化元数据或图片；固定编译器输出内部 `renderBundle`，工具 schema 不向 AI 开放 HTML、SVG、样式或编译片段参数。编译包绑定版本、源文摘要和各任务的输入摘要，最多 8 MiB / 41 个任务。服务器以 Goldmark 重新检查 Markdown，派生目录、搜索文本和媒体引用，只将验证后的富内容片段装配进正文；页面模板继续由服务器统一生成。

服务端验证片段的元素、属性、命名空间、代码原文、公式源文注释与资源引用；拒绝脚本、事件属性、外部 CSS/SVG 资源、外部实体和页面 HTML。摘要用于一致性校验，不能证明生成进程的身份或公式/图表的语义正确；管理 token 仍拥有全部管理权限。安全边界来自服务端约束，MCP 工具接口保证正常 AI 发文经过固定编译器。

修订和备份保存编译包。回滚复用当前格式的包；旧包通过 MCP 本地重编译。导入当前备份时从源文和包重建，忽略缓存 HTML；旧备份先由 MCP 离线更新包，再由服务器完成关系校验、预览与确认恢复。编译器升级不在服务端启动时运行 Node，旧发布页保持可读，更新缓存后仍走明确发布流程。
